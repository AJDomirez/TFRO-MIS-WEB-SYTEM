Head Administrator

Full system supervision.

  • Dashboard, records, approvals, reports, notifications, and audit log
  • Create/delete restricted Administrators and TFRO Staff accounts
  • Manage system settings and destructive actions

Restricted Administrator

Operational administration without destructive authority.

  • View, add, edit, save, verify, and approve operational records
  • Cannot delete/archive records
  • Cannot manage accounts or system settings

TFRO Staff

Violation and payment processing.

  • Encode and update violation records
  • Verify payment evidence and record settlement/release
  • Print official notices and payment-related forms

Operator

Self-service regulatory portal.

  • Apply for a franchise and manage driver submissions
  • Submit renewals and change-motor requests
  • Upload requirements/receipts and receive notifications

Traffic Enforcer

Field enforcement portal.

  • Search/verify drivers using QR information
  • Create violation tickets and upload ticket photos
  • Cannot record payments or access administration
Who can create an account: Operators register publicly. Traffic Enforcers may register only when their Enforcer ID matches an active roster entry created by an Administrator. Head Admin creates Restricted Administrator and TFRO Staff credentials in Admin Users. Drivers are managed records submitted by Operators; drivers do not have a login portal.
Roles come from the protected profile record—not browser storage or editable user metadata.

APPROVED

The application is linked to a new franchise record, the tricycle record is created, and administrator/date information is stored.

REJECTED / NEEDS CORRECTION

The reviewer records a reason. The operator is notified and can correct the requirements according to the displayed status.

Required evidence

Voter’s certificate, barangay clearance, cedula, OHCR, insurance, and PMBL certification.

Important rule

Submitting an application does not create an approved franchise. Creation happens only through the approval workflow.

Driver records

Operators submit driver details and pictures; authorized administrators review, assign, and verify compliance.

The application, documents, franchise, tricycle, operator, and notifications remain linked through database identifiers.

Operator checks eligibilityThe selected franchise must be linked to the signed-in operator and allowed to renew.
Operator uploads requirementsRequired documents and the 2×2 picture are validated by type and completeness.
Administrator reviews documentsEach requirement is marked verified, rejected, or requiring correction.
Administrator records assessmentInspection results, fees, payment verification, and hard-copy requirements are recorded.
Administrator approvesApproval is allowed only when the required review conditions are satisfied.
System synchronizes franchiseThe new expiration date is applied and the previous MTOP expiration is preserved.
COMPLETE

Renewal becomes approved, printable forms become available, franchise expiry is updated, and the operator receives a notification.

INCOMPLETE

The request stays pending/reviewing or is returned with remarks until the operator supplies acceptable requirements.

Control point

Approval should never be used to bypass missing documents, inspection results, assessment, or payment confirmation.

Printable output

The system can prepare renewal checklist and related official forms using the saved record.

Traceability

Submission attempts, reviewers, dates, verification results, and approval activity are retained.

Renewal processing preserves the former expiration value for historical comparison.

Account Management

  • Head Admin creates restricted Admin and TFRO Staff credentials
  • Head Admin can reset supported portal passwords
  • Clicking an account opens its attributable activity history
  • Deleting access preserves operational history where required

Notifications

  • Approval, rejection, correction, expiry, and workflow messages
  • Personal notifications are visible only to the intended account
  • Read/unread state helps users track action items

Reports and Exports

  • Filter operational records and review summaries
  • Generate CSV exports and print official forms
  • Dashboard totals summarize current database records

Audit and Security

  • History shows date, action type, action, description, and affected record
  • Account history is matched by protected user ID—not by display name
  • Row Level Security protects records by role and ownership
  • Service-role credentials remain inside server-side functions

Recommended daily operating sequence

Sign in with your own accountNever share credentials or leave a logged-in workstation unattended.
Review notifications and pending countsUse the dashboard and portal notices to prioritize transactions.
Open the correct workflow pageAvoid direct database edits; use the UI process that preserves validation and history.
Verify evidence before decidingCheck uploaded documents, identities, receipts, and linked records.
Record clear remarksRejection, correction, inspection, and release notes should be specific.
Confirm the result and sign outCheck the updated status/notification, then securely end the session.
Use this guide with current TFRO policies and authorized office procedures. System permissions do not replace administrative review.

Administrative decision

Verify the linked person, franchise, files, dates, and required checkpoints. Use specific correction/rejection remarks so the Operator knows what to fix.

Official outputs

Print from the completed saved record. Available outputs include notices, payment/release forms, renewal forms, and change-motor forms.

Audit limitation

Account History shows actions actually written to the audit log. Absence of an entry is not proof that no offline or unlogged event occurred.

Head Admin account history is filtered by protected user ID, so users with similar names are not mixed.
Quick reference

12. Where to Go in the System

12

Administrator Pages

  • Dashboard: operational overview and pending totals
  • Applications: review new franchise applications
  • Franchise / Operators / Drivers: master records and assignments
  • Renewals / Motor Requests: assess and decide requests
  • Violations / Payments: monitoring and authorized operations
  • Reports / Audit Log: oversight, export, and complete traceability
  • Profile → Account Credentials: click an account to inspect its action history
  • Admin Users: create/delete restricted Admin and TFRO Staff accounts

Operator Pages

  • Operator Portal: franchise summary and service status
  • Apply for Franchise: new application and document upload
  • Driver Submission: add/update pending driver information
  • Renewal: submit requirements and track review
  • Change Motor: request replacement of vehicle details
  • Notifications / Profile: messages and account information

TFRO Staff Pages

  • Violations: encode and monitor cases
  • Payments: verify receipt, record settlement, release unit
  • Profile: personal account details and password
  • Other pages appear only when the role is authorized by system policy.

Traffic Enforcer Pages

  • Enforcer Portal: field ticket activity
  • Driver Verification: scan QR or enter verification token
  • Violation Submission: ticket data and supporting photo
  • Profile: personal account details

Status meanings

Pending: waiting for action. Reviewing: assessment underway. Approved/Paid: required decision completed. Rejected/Correction: user action is required.

If something fails

Read the displayed message, verify your internet connection and role, refresh once, then report the record number and exact error to the Head Administrator.

Printing this guide

Choose A4, Landscape, Default margins, 100% scale, and enable Background graphics. Use “Save as PDF” to distribute electronically.
